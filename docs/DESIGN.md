# 设计说明

本插件是 DeepSeek Harness 的浏览器端交互层，目标是提供一套克制、键盘优先、与宿主原生能力不冲突的界面增强。所有能力都建立在宿主公开的插槽（Slot）和服务（Service）之上，不修改宿主文件，也不替换应用根节点。

## 设计原则

1. **只在官方座位渲染**：主题走 `theme.overrideTokens` 令牌层；运行条、面板、朗读、页脚、设置分别注册到 `conversation.input.dock`、`shell.overlay`、`conversation.chat.assistant-actions`、`conversation.chat.turnTail`、`settings.section` 等公开插槽。对话流、工具卡、审批、输入框和队列仍由宿主拥有。
2. **可逆**：主题是覆盖层，关闭开关即移除；所有组件随插件上下文销毁；卸载后不留下全局样式或定时器。
3. **降级而不是崩溃**：缺服务、缺槽位、缺浏览器能力时，对应控件隐藏或退化为无操作，其余功能不受影响。
4. **键盘优先，但不抢宿主键位**：只接管空输入框里的 `↑/↓`、`?`，以及明确的 `Alt+B`、`Alt+N`、`Ctrl+K`；`Tab`/`Esc` 只在存在可见 ghost 建议时生效，所有监听都先检查 `defaultPrevented`、输入法、运行态与弹层状态。
5. **无外部品牌资产**：状态星是 Unicode 字符 `✻`（U+273B），按钮图标为内联 SVG，不包含第三方图标、字体或截图。

## Prompt Pilot 的边界

- **完整草稿优先，AI 是增强不是前提**：读取当前 Chat 快照中的最新助手回复、最近工具结果、上一条用户提示词和会话标题，先在本地生成一条包含目标、已知上下文、范围、约束、执行方式、验收/验证的完整草稿，用多行卡片完整显示；开启 AI 完善后，再把同一份受限上下文交给当前模型改写。关闭开关或模型不可用时，完整草稿仍然可用。
- **AI 只为同一上下文调用一次**：客户端按上下文 hash 缓存；Host 路由再按上下文 + 模型选择缓存 10 分钟，并在缓存命中时跳过限流。失败（网络、鉴权、无模型、空输出、`SKIP`）在客户端有 60 秒失败冷却，避免反复消耗 token。输出预算 650 tokens，输入上下文在 Host 侧再次裁剪。
- **可撤销、可冷却**：空输入框先经过 350ms 聚焦停留；`Tab` 接受、`Esc` 收起；收起按建议 key 冷却，避免同一条建议立刻重现；接受只计入统计，不冷却——用户删掉刚接受的草稿后，建议应能从缓存再次出现且不重复请求模型。
- **只存聚合统计**：localStorage 只记录建议类别、出现/接受/收起次数和 key 时间戳，不保存提示词正文，也不跨设备同步。
- **完整显示**：完整草稿不再塞进单行 ghost，而是固定定位的多行卡片；正文 15px、可换行、卡片内可滚动，移动端不横向溢出。

## 参考与取舍

- **Claude Code 的 prompt suggestion**：用灰色后续文本、`Tab` 接受（[说明](https://verboo.ai/en/blog/claude-code-prompt-suggestions)）。本插件保留单条、内联、显式接受的低摩擦形态，但把“短句”升级为完整提示词卡片。
- **ChatGPT 的 prompt starters / 提示词编辑**：空态给与情境相关的起始建议，并允许把一句话扩写成更完整的请求（[模式说明](https://aiuxplayground.com/pattern/prompt-starters)）。本插件用本地草稿保证即时性，再用当前模型做一次有上限的改写。
- **Copilot 式 inline ghost**：前缀补全仍是内联 ghost；空输入框的完整草稿不抢焦点、不自动发送。

### Prompt Pilot 的完整提示词规则

本地草稿必须以用户可直接发送的口吻写出完整任务，而不是产物名或短句：

- 目标：这一轮要达成什么；
- 已知上下文：最近结论、上一条提示词或会话标题中已经确认的事实；
- 范围与约束：改动边界、不能假设的文件/命令/数字；
- 执行方式：具体下一步或步骤；
- 验收/验证：完成后运行什么检查、比较什么结果、汇报哪些风险。

没有明确下一步的报错也会生成一条完整的诊断草稿（复现、根因假设、修复后同一验证与剩余风险），而不是静默消失；匹配用户最近使用的语言；不编造上下文中不存在的事实。模型改写只做“更完整、更可执行”的编辑，不新增未出现的文件、数字或结论。另加 350ms 心跳轮询，宿主弹层关闭、React 重渲染或事件顺序异常后仍能重新显示卡片。

## 数据与存储

DSH 的默认数据模型是单根：`configured > $DSH_HOME > ~/.dsh`。Windows 桌面版还会把 Electron userData、更新器缓存、pnpm/npm 缓存和临时目录写到用户目录；这些位置不都由 `DSH_HOME` 控制。插件不另造解析器，只按同一优先级展示逻辑路径与 `realpath` 后的物理路径。

- **只读审计**：Host 扫描 `harness-home`、`desktop-profile`、`updater-cache`、`pnpm-store`、`pnpm-cache`、`npm-cache`、当前 TEMP 与系统 TEMP。用 `lstat` 判断 reparse point，用 `realpath` 找物理目标；遍历时跳过子 junction，避免把链接目标重复计入。单次扫描有 120k 条目 / 4s 上限，触顶的数值标 `≥`，不伪装成精确值。
- **迁移是事务，不在插件里执行**：Host 只生成可审阅的 PowerShell。脚本先检查 DSH 进程，`robocopy /E /COPY:DAT` 复制，比较源/目标字节数，把原目录改名为 `*.data-keeper-<时间戳>`，再建 junction 并验证 `LinkType`；任何一步失败都把原目录改回。旧副本从不自动删除。源/目标重叠、目标是驱动器根、目标已存在都拒绝。
- **临时目录只清不搬**：系统 TEMP 建 junction 会影响其他程序，也可能被宿主更新覆盖。清理脚本只匹配 TEMP 下直接子项中名称以 `dsh-` / `dsh_` 开头的旧项，默认 dry-run，`-Apply` 才删；reparse point 和被占用项保留，且永不触碰 DSH 主目录。
- **与成熟范式对齐**：Claude Code 用默认 30 天的 cleanup 周期与白名单；VS Code/Electron 迁移要求先停写、`app.setPath` 在 ready 前、同一 user-data-dir 不能双开；Chromium 同样要求单实例。插件的“停 DSH → 复制 → 校验 → 切换 → 可回滚”就是这套事务顺序的保守实现。

## 视觉与主题

- 两套完整令牌：中性炭黑（暗）与中性浅灰（亮），由 `theme` 服务按当前亮暗偏好选择。
- 品牌色为陶土橙 `#d77757`，用户消息块、输入区、选中态、success/error/warning 与 diff 颜色都经过统一整理；只覆盖 `--dsw-*` 令牌，不写宿主选择器。
- 运行状态星的六帧脉冲、回合页脚的完成词、动词池都是插件自己的展示层设计。

## 动效与可访问性

状态星逐帧脉冲、面板入场和控件过渡都遵循 `prefers-reduced-motion` 与插件内的「动效」开关。面板使用 `role="dialog"`、`aria-modal`，开关使用 `role="switch"` 与 `aria-checked`，分段控件使用 `aria-pressed`，所有按钮保留可见焦点环和可读标签。
